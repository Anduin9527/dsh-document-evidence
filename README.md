# DeepSeek Harness 文档资料库

中文 · [English](README.en.md)

可直接安装到 **dsh Web** 的原生 Cordis 插件。上传 PDF 后确认加入项目资料库，后台建立索引；回答中的文档引用可以打开右侧原文、跳到物理页码并高亮对应文字。

测试版：`0.2.0-beta.9`。兼容基线是 **npm 发布的 `@deepseek-ai/dsh@0.1.3-alpha.2`**，并非同版本号的最新 GitHub 源码。已发布版本使用原生右侧详情栏，关闭文档后恢复原详情；另保留新 `sidebarRight` 接口适配，但该分支未在完整源码构建中验证。

## 安装与启动

需要已能运行的 dsh，以及 Python 3.10+（含 venv）。获取维护者提供的版本安装包后执行（发布前不要假设 npm 上的同名包属于本项目）：

```sh
dsh plugin --profile web add /absolute/path/dsh-document-evidence-0.2.0-beta.9.tgz
dsh plugin --profile web exec dsh-document-evidence-setup
dsh web
```

第二条命令只建立插件专用 Python 环境并安装 PyMuPDF，不写模型设置，不需要 API Key。已安装 PyMuPDF 时也可以在配置中指定自己的 Python，省略这一步。安装依赖需要联网；解析、检索与渲染在本地运行。

插件直接复用 **dsh 中已配置的模型和凭据**，不需要再提供一套 Key。真实问答需要 dsh 模型配置可用；扫描页处理和图像读页需要当前模型明确声明图像输入能力。缺少视觉能力时，文字索引仍可用，界面显示未处理页数。

本次验证发现 Node `24.1.0` 下官方 dsh 的命令入口可能无输出；若遇到这种情况，请升级 Node 后重试。插件测试使用显式调用官方 `runCli()` 的方式启动该运行时。

## 第一次测试

1. 在 dsh 选择项目，上传 PDF 并发送消息。
2. 会话右上角的「资料库」显示待加入提醒。打开后点击「确认加入并索引」。也可以选用面板列出的项目 PDF。
3. 查看文字覆盖页数和视觉页卡数量。处理中可以提问，停止后可以续建。
4. 勾选这次对话需要检索的文档，然后提问，例如：

   > 查一下这些手册对审批默认值的规定。核对原页，使用资料库引用；有不同规定时分别列出依据。

5. 点击回答中的「文档名 · 第 N 页」引用。对话旁的原文侧栏显示相应页和高亮；支持翻页、缩放和关闭。窄屏空间不足时改为浮动文档栏，关闭即可完整返回对话。

同项目新会话可以复用已有资料；每个会话的勾选范围独立保存。添加时保存 PDF 内容快照并按 SHA-256 去重；源文件修改后再次加入会形成新的内容身份，旧引用继续对应原快照。

## 索引与检索过程可视化

展开对话里的工具调用过程，可以看到四种原生卡片：文档索引、检索、读页和引用定位。卡片显示真实运行/完成/失败状态及耗时，保留「查看原始轨迹」入口。

- 检索显示查询词、本会话范围、每份资料的文字覆盖、命中页数、候选页分数和摘录。点击页码打开 PDF 原文。每份资料最多展示12个返回候选页，其余仍在原始轨迹中；分数不代表答案置信度。
- 索引过程显示开始、文字批次、视觉页处理、摘要、完成/视觉缺口/中断/失败。资料库侧栏轮询实时进度，每份文档保留最近80条记录，重启后继续可见。旧索引没有历史事件时明确提示，不要求重建。
- `library_list` 的原生卡片保留调用时的索引时间线快照，后台后续进度在资料库中查看。详细时间线通过 Host 的 presentation metadata 保存，不进入模型文字上下文，不调用模型来生成 trace。
- 检索和读页沿用真实工具生命周期；后台索引不伪造 Agent 工具调用。当前没有把后台各批次作为独立行加入 dsh 的「轨迹」时间轴。

`0.2.0-beta.7` 同时修复模型将整数页码写成字符串时的工具错误：只规范化无歧义的正整数字符串，保留整数 schema，小数、负数和超大值仍拒绝。

## 实际能力与边界

- **文档目录**：名称、内容身份、简介、关键词、大纲、覆盖状态和会话范围。简介由当前模型基于前部摘录、大纲及已有页卡整理，仅用于路由。不能确认的版本、生效日期和适用范围显示「未知」。
- **检索**：中文二字词和英文词面检索，结合视觉页卡。检索覆盖每份选中文档，不按摘要做硬过滤；空结果或部分索引不能证明全文没有答案。
- **视觉**：低文本页通过 dsh 当前视觉模型建立检索页卡；主 agent 可以进一步看任意候选页的真实图像。页卡是模型笔记，不是经过校验的 OCR。图表、表格和公式的解读准确性取决于模型，已用真实 PDF 做有限案例核对，尚无大规模准确率结论。
- **高亮**：使用原 PDF 的字符布局坐标，支持跨行引文、重复匹配和旋转页。没有可匹配文字层的扫描页只跳到原页并说明精度，不猜坐标。此版未引入带布局的 OCR，也未实现自动识别整张表格/矢量图的边界。
- **后台任务**：最多同时处理两个文档，按批保存文字进度，逐页保存视觉页卡。停止会取消正在运行的工作；重启后标为中断，由用户续建。资料库写入按单个 dsh Host 进程设计，不支持多个 Host 并发写同一缓存目录。
- **定位方式**：侧栏显示从不可变 PDF 快照渲染的原页图像，支持物理页导航和缩放；不是通用 PDF 编辑器。引用链接只在装有本插件的 dsh 中生效。

资料库负责候选、读取和定位，主 agent 负责回答、有限查询改写、邻页补读、冲突解释及是否使用 dsh 现有联网工具。引用定位不等于自动语义验证。

## 配置

默认数据目录为 `$DSH_HOME/data/document-evidence`（未设置 DSH_HOME 时为 `~/.dsh/data/document-evidence`）。安装辅助程序创建的 Python 会自动被使用。项目身份从 dsh 当前会话的 sandbox workspace root 推导；上传只接受已提交到该会话的可信附件引用。

可在 `$DSH_HOME/profiles/web/cordis.patch.yml` 添加覆盖配置：

```yaml
- id: document-evidence
  config:
    python: /absolute/path/to/python
    cacheDir: /absolute/path/to/document-evidence
    maxPdfBytes: 104857600
    maxDocumentPages: 2000
    timeoutMs: 120000
```

默认单文件上限 100 MiB、2000 页；图像最长边 2400 像素；项目发现限两层子目录、1000 个目录项、50 份 PDF，跳过隐藏目录、node_modules 和符号链接。超过发现范围时可直接上传或自行加入对应文件。

`python` 与 `cacheDir` 支持 `auto`。每份 patch 的 `config` 替换整份配置，未填写的字段使用默认值。更改 Python 配置后重启 dsh。

## 原生工具

| 工具 | 用途 |
|---|---|
| `library_list` | 当前项目目录、会话范围、上传候选和有界项目 PDF 发现 |
| `library_retrieve` | 一次完成有界候选检索、原页摘录和引用定位 |
| `library_expand` | 补读选定页和可选邻页，返回证据与未读缺口 |
| `library_search` | 检索本会话选中的文档并报告逐文档覆盖 |
| `library_read_page` | 读取原页文本和可选真实图像附件 |
| `library_cite` | 对已读页生成有可靠坐标或明确页级降级的引用 |

开发兼容项 `enableStandaloneTools: true` 可额外启用早期 `pdf_*` 单文件工具及 HTML 导出。这些工具使用独立 `allowedRoots` 配置，默认关闭；正常资料库使用不需要它们。

### beta.4：分层检索与逐文档补查

优先使用 `library_retrieve({query, ids?, top?})`：复用现有索引，在一次工具调用中完成候选检索、原页文字读取、连续原文片段提取与引用定位，无内部模型调用。默认全范围最多8个候选页、16000 UTF-8 JSON字节、12份文档，每轮最多3次宽泛 search/retrieve，另为每份文档提供3次定向 search/retrieve/expand。配置项为 `maxRetrievalPages`、`maxRetrievalBytes`、`maxRetrievalDocuments`、`maxRetrievalCalls`。字节预算不等于 tokenizer token 预算，也不限制后续显式读图/读整页的大小。

`ids` 只能缩小当前会话范围。跨文档轮流取候选，避免直接比较各文档独立计算的分数；不是语义重排。同轮完全相同的摘录仅返回引用标记，新的片段仍发送。完整候选和读取轨迹保存在展示 metadata 中，模型只收到紧凑证据包。列表只返回所选资料的简短摘要，侧栏保留完整目录与索引历史。

`text_evidence` 仅表示已提供原文，不保证支持答案；扫描、低文本或检测出的乱码页返回 `needs_vision`，应继续读取原页图像。检索未命中和预算未读必须作为缺口报告。引用工具检查已读取页面或已送达片段，并做原文定位；尚未拦截模型最终正文中自行编造的引用，也不自动验证数字、年份和语义。


简单定位题先用 `library_retrieve`；多文档比较必须逐份核对指标、年份、单位，缺口用 `ids:[id]` 定向换词。`library_expand({id,pages:[物理页号],query,neighbors:true})` 接受1–4个选中页，默认自动补前后邻页，种子页优先、去重并限定合法页号。深读最多8000字符/页，仍遵守单次16000字节预算；返回 next 指出读图、单页补读、截断上下文或文档定向检索建议。大页单独补读时自动缩小连续原文窗口，不伪装成完整页面；需要窗口外内容可用 library_read_page。

表格、图表或布局不确定时，主Agent通过已有 `library_read_page(image:true)` 看图判断候选，再补读相关页与邻页。这里复用了主Agent的视觉能力，没有在工具内部增加独立视觉精排模型。模型是否遵循策略、是否选对页仍需实测。默认每轮检索上限随实际选中文档增加（宽泛3次、每文档定向3次）；比较题可能使用更多token来补全证据。次数耗尽只能报告缺口，不能据此判定资料没有答案。

### beta.5：原生目录和检索过程

资料库每份PDF提供「目录与建立过程」：分层显示已保存的原PDF书签；无书签明确提示，不生成语义章节。页面索引按25页分组，展开后可点击页码打开原文；「索引建立」显示当前阶段状态和真实历史事件。旧索引无事件时不补造时间线。

原生工具卡片的「检索过程」支持点击候选页查看摘录、送达状态、预算遗漏、重复片段和原页。外观使用dsh主题的字体、文字色、边框、悬停及选中状态，支持主题切换。过程来自当前工具的presentation metadata，不向模型额外发送展示内容。

### beta.6：知识库入口与文档浏览

顶栏资料库按钮对齐dsh原生Session日志按钮尺寸与主题，显示本会话选中文档数。面板改为可搜索的紧凑文件列表，选择查看文件与勾选检索范围分离，只展开当前文件详情，添加资料收在独立折叠区。信息组织参考Dify/RAGFlow的资料列表、文件解析详情与检索检查分层；未引入其服务或新增检索策略。

### beta.7：选择范围一致性

模型检索、展开、读页和引用均限于当前会话所选 PDF。切换范围使旧读页／片段授权和去重记录失效；调用期间切换范围会拒绝过期结果。人工侧栏仍可浏览其他项目资料。最终回答由主 agent 生成，尚无自由文本答案的语义核验层；协议替身不用于真实问答验收。

### beta.8：批量读取与证据复用

同文档多页正文、定位合并为批量 Python 操作；显式 Figure/Table 编号优先匹配原文图表标题。`reuseVisibleEvidence` 复用当前模型上下文中同文档同页的完全相同片段和图片，原始工具记录仍完整保存。引用包含原始事件位置和文本 SHA-256；历史压缩移除或改写引用来源时，从日志恢复必要的原文片段。原生固定请求的 provider 输入从 27,697 降到 26,760 token（−3.38%）；同一论文的暖索引 retrieve 中位数从 1,544 ms 降到 359 ms。一组真实追问从 41.1 s 降到 28.5 s，但首 token 和未缓存输入未改善，不能据此宣称所有场景或费用都更低。`reuseVisibleEvidence: false` 可关闭上下文复用。完整方法、来源保留检查与限制见[验证摘要](docs/optimization-beta8.md)。

## 支持范围与数据流

| 项目 | 状态 |
|---|---|
| dsh Web npm `0.1.3-alpha.2` / macOS arm64 | 已验证 |
| 新版 dsh / 源码构建的 sidebarRight | 未完整验证 |
| Linux / Windows | 尚未完成原生 Web 验证 |
| Python | 3.10+，发布配置固定 PyMuPDF 1.28.2 |

PDF 快照、文字索引与页卡保存在本地。后台摘要、低文本页视觉页卡，以及主 agent 的证据问答会把相应摘录或页面图像发送到 dsh 当前配置的模型服务，并消耗该服务用量。安装 Python 依赖会连接包索引；插件不要求自己的 API Key。

### 卸载

```sh
dsh plugin --profile web remove dsh-document-evidence
```

然后重启 dsh。卸载保留本地资料库和 Python 环境；只有确定不再需要原文及旧引用时，再手动删除配置中的缓存目录。不要删除正在使用的共享资料目录。
